# Security and data-loss considerations

The Phase 4 release candidate accepts local profile/work entries and strictly validated backup replacement through a revision-aware adapter. Backups and printed/PDF reports contain private unencrypted data; review file/print destinations and verify external copies. Physical-device, screen-reader and hosted acceptance remain incomplete. Production sends no application analytics and loads no remote resources; evidence links navigate externally only when clicked and use noopener/noreferrer. The hosting provider receives ordinary HTTP requests. No server storage or authentication is planned. Device users, browser extensions, malicious same-origin scripts and compromised devices are outside IndexedDB's protection; it is not encrypted storage. Browser profile and origin (including local port) define the storage boundary.

| Threat                                    | Design response                                                                                                                                                                                          |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| User content injection                    | React text rendering; no unsafe HTML; validate evidence URLs, never execute backup content                                                                                                               |
| Malformed / oversized backups             | 5 MiB UTF-8/file byte bound, strict envelope/value/aggregate checks, reject before any transaction                                                                                                       |
| Accidental replacement or deletion        | Explicit modal acknowledgement and current-record export opportunity; transaction rollback on failure                                                                                                    |
| Browser eviction, clearing or device loss | Explicit honest messaging; portable JSON backups with verified-copy guidance                                                                                                                             |
| Worker cache leakage                      | Only build-time asset allowlist, exact URL matching, scope-specific revision cleanup                                                                                                                     |
| Stale worker / mixed versions             | No skipWaiting; new revision activates after old tabs close                                                                                                                                              |
| Dependency compromise                     | Lockfile, npm audit high gate, review license/dependency changes                                                                                                                                         |
| Concurrent edits and upgrades             | Atomic revision comparison rejects stale writes; corrupt data is preserved; handles close on versionchange. UI blocks stale saves until explicit refresh, keeps drafts and shows conflict/retry guidance |

The HTML CSP restricts resources to the same origin, disables objects, base changes and form submissions; injected inline CSS and local WebSocket access are permitted only by Vite development serve mode and are absent from the production policy. Static hosting headers (including frame-ancestors) cannot be set through meta tags and remain a deployment consideration. Treat hosting the app beside untrusted same-origin content as unsafe. No secrets or real records in issues, logs or test artifacts. Reports use React text rendering; backups use JSON serialization, never generated executable markup; no CSV is approved in the MVP.

See root SECURITY.md for reporting. This foundation is not a security certification or a complete WCAG audit.

Phase 4 distribution checks allow only reviewed static files, reject symlinks and development harnesses, and enforce size budgets. Workflows pin official action commits, keep build credentials read-only and isolate Pages/OIDC write permissions to the manual deployment job. Neither the workflow nor the application creates accounts or uploads student records. These checks do not provide comprehensive security certification or protect against compromised same-origin code/device users.
