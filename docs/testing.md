# Verification

Run `npm ci`, `npm run check`, `npx playwright install chromium firefox webkit`, `npm run test:e2e`, and `npm audit --audit-level=high`. Linux CI installs browser OS dependencies with `npx playwright install --with-deps chromium firefox webkit`. Browser downloads need network access. Tests use synthetic content and no accounts. The Playwright web server always builds production output first; `npm run dev` deliberately has no service worker.

`check` runs typecheck, zero-warning ESLint, Prettier, Vitest V8 coverage and production build. Registration tests cover unsupported/development/success/failed/stalled setup. Workflow integration uses the actual hook, domain and IndexedDB adapter with a fresh fake-indexeddb factory, including React StrictMode, invalid submissions/field focus, CRUD/reload, distinct duplicates, profile date containment, dirty cancellation, quota failures, pending commit and stale-tab draft recovery. Startup waits allow five seconds for cold CI/Windows initialization; no startup performance claim is inferred. Generated reports are ignored by Git.

Production browser tests exercise keyboard skip links, desktop/mobile layout, axe WCAG A/AA rules, safe links, accessible delete confirmation, complete CRUD, saved-record reload, actual offline saved-profile/entry reopening and further offline saves, stale-tab refresh/resubmission, denied storage, and explicit cache contents under a repository subpath. Automated axe results do not replace a full accessibility audit. Modal behavior is covered in Chromium, Firefox and WebKit; jsdom uses a minimal open/close fixture only where it lacks the native API.

Coverage includes app and infrastructure source; the React root bootstrap is excluded because browsers exercise it. Domain coverage gates require >=95% statements/lines/functions and >=90% branches. Domain tests cover real/invalid calendars (including years below 100, leap centuries and year boundaries), integer-minute precision, target/entry/text/URL limits, duplicate IDs, aggregate daily limits, deterministic grouping and excess progress. Codec tests cover Unicode round-trips, hostile markup as plain text, malformed/unknown envelopes and UTF-8 size limits. Do not inflate coverage with trivial implementation-mirroring tests.

IndexedDB integration tests use fake-indexeddb with a fresh factory per test. They cover initial schema upgrade 0→1, reload, edits/deletes, current data validation, conflicts/concurrent writers, missing/corrupt records, quota and abort rollback, incompatible schemas/future versions, denied storage, initialization failure, and late timed-out opens. The blocked-event guard is explicitly simulated: schema v1 has no prior released schema whose connection could block a 0→1 upgrade. Quota/abort injection tests failure behavior, not physical disk exhaustion.

Playwright additionally starts a development server on port 4174. A test-only module fixture continues to verify adapter-level page reload persistence, offline read/write/connection reopening and native cross-tab conflict handling. Production UI/offline tests run on port 4173. The fixture is not imported by the app and is absent from dist. Keep our manual preview servers off port 4173 during tests; a running Windows server can also lock native build binaries during npm ci.

When connected, use the owner's installed Chrome for a visible smoke review with synthetic data on a separate local test origin; preserve existing records and cached versions. Record exact checks and proof separately from Playwright's bundled Chromium. Manual release checks remain: physical Android/low-end device, installed Safari/iOS, screen reader, installation UX, storage eviction, native printer/PDF settings and deployed Pages. Automated Firefox/WebKit, reflow/text-size and worker-lifecycle checks now supplement Chromium. No legacy migration exists yet; preserving migrations need tests when schema actually changes. Verify print/PDF output and backup downloads on each supported release browser. Record dated actual outcomes in PROJECT_CONTEXT.md; never carry forward passing claims after relevant changes.

Phase 3 adds portable codec/file tests (unknown envelopes, hostile text, invalid nested/aggregate data, Unicode byte limits and read/encoding failures), real-session replacement tests (cancel, fresh/empty restore, quota rollback and conflict refresh/review), and exact multi-day/week report assertions. Browser checks exercise actual downloads, offline round-trip restoration, invalid/oversized input without replacement, cancellation with a retained draft, stale-tab re-review, axe, narrow-screen overflow and saved-data-only printing. Print-media screenshots and generated PDFs live under ignored `test-results/`; inspect PDF page renders for pagination, long text, Unicode and signatures. Browser print success is not proof of physical printer output or durable external backup storage.

Phase 4 adds 320px/landscape/tablet and 200% root-text checks, reduced motion, cancel-focus restoration, local-only request and CSP checks, PNG dimensions, native print preparation without preview, paging with all-record preservation and 1,000/10,000-entry capacity measurements under 4x CPU throttling. Reported timings are local synthetic observations, not field benchmarks. Structural rendering limits and exact backup equality guard against regressions without fragile time thresholds.

Worker lifecycle fixtures serve the real worker template/build assets from isolated ephemeral origins. They test failed precaching, waiting while old clients remain, activation of a new revision after closing them, scope-specific cache cleanup, preservation of unrelated caches and persisted records, and offline reopening. A fixture-only message acknowledges the worker revision; main-page polling confirms activation and cache state before asserting new HTML. The test retains direct cache contents and document assertions. Precache failure intentionally returns a synthetic 503; it is not a production-network reliability claim.

All engines exercise core workflows and print media; Playwright's Chromium-only PDF API remains conditional to that engine, not a skipped workflow. Native screenshot/PDF artifacts and capacity attachments are ignored under test-results. The build's check-dist.mjs verifies the public asset boundary and numeric gzip budgets. Pages workflow YAML is parsed by Prettier and reviewed against official action inputs/permissions; execution/live deployment remains NOT VERIFIED until owner publication. See release.md for exact owner steps and limitations.

The development-page browser regression also verifies computed application styles, Vite style injection and absence of CSP violations in every engine. Production policy checks remain separate.

Local-network entry regression: route real production assets to a reserved HTTP test hostname, assert isSecureContext is false and randomUUID is unavailable, then save a 10-hour synthetic entry, reload and edit it without duplication. All browser projects run this check. This exercises actual non-secure-context API restrictions without exposing a server to the LAN; physical iOS/Android retesting remains separate. The ID helper tests UUID version/variant formatting from boundary random bytes; randomness comes from Web Crypto, never Math.random or timestamps.
