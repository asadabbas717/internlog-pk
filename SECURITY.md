# Security policy

This is pre-release software. Only the current repository state is maintained; no supported release series or response SLA is established. The Phase 4 release candidate accepts local profile/work entries and validated whole-logbook backup replacement. JSON backups and printed/PDF reports contain private, unencrypted details; protect those files and verify copies. Use synthetic records until owner device/recovery acceptance is complete.

For a sensitive vulnerability, use the repository's GitHub **Security → Advisories → Report a vulnerability** if private reporting is enabled. If unavailable, request that maintainers enable a private reporting channel in a public issue **without exploit details or personal data**. No private contact address has been established. Never include real student data, credentials or confidential evidence in public reports.

Include the affected revision, a synthetic reproduction, expected/actual behavior and impact through an available private channel. See docs/security.md for threat boundaries. Local browser storage is not encrypted or permanent, and compromised devices/extensions or same-origin scripts may access it. No security certification is claimed.
